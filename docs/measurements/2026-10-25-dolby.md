# Dolby 双路输出验收（2026-10-25）

本轮为 PoseBridge 0.7.0，目标为 macOS Apple Silicon 和 Windows x64。
同一核心采集任务并行发送 PoseBridge OSC 3 和 Dolby `/ypr`，仅 Dolby 支持本会话软件回正。
使用方法、坐标边界和新增 Rust／C 导出见 [Dolby 指南](../dolby.md)。

双路集成测试使用临时端口，不占用真实 Renderer 端口。
C ABI 窗口中 PoseBridge 上限 20 Hz、Dolby 上限 100 Hz，约 0.7 秒收到 14–15 个 PoseBridge 姿态包和 69–70 个 Dolby 包。
CLI 上限分别为 100／50 Hz，约 1 秒收到 100–102／50–51 个姿态包。
每份 Dolby 数据报均独立解码验证为 28 字节 `/ypr`、`,fff`；没有额外心跳或元数据。
这些数量是短测试窗口中的结果，不是硬件速率或时延测量。

测试还覆盖不同输出速率、去重与合并、编码失败的独立计数和故障隔离、接收器关闭、停止、
500 ms 过期及无数据回正、下一份新采样生效、重连／参考代次变化后的清除。
回正前后原 PoseBridge 四元数、参考代次和元数据版本不变；原 OSC 3 心跳没有新增 Dolby 字段。
停止测试保留原有最后一条状态心跳，禁止继续发送姿态。

客户端覆盖版本 1 配置迁移、PoseBridge 旧目标／格式保留、Dolby 默认关闭、未来配置只读保护、
两路开关独立、软件回正不重启连接，以及宽窄窗口和滚动后两路红色错误的可见性。
磁场 PTY 测试等待假串口收到已发送的 SAVE 后再断言，避免把主机异步交付误判为漏写；没有改变设备写入行为。

## 本机 Dolby Atmos Renderer 5.5

兼容基准为 macOS Dolby Atmos Renderer 5.5.0 正式版及随附 OSC 头追驱动。
已安装驱动的 SHA-256 为：

```text
a361db6d42ee377ec99791582270eb5ecc1634ac2abdd3f84df5eb6373d401cc
```

驱动接收端为 UDP 8000，接收 `/ypr` 三个 float32 度数。
独立调用已安装驱动的 YPR／矩阵入口，7 组零姿态、单轴、复合和极点输入与所记录矩阵公式的最大分量误差为 `2.95e-8`。
此项验证矩阵约定，不用它替代实际网络接收或听音。
核心测试另外比较 672 组含 q／−q、±180° 和俯仰极点的物理旋转及 Dolby 驱动矩阵，容差为 `2e-6`。
相对姿态由四元数相乘求得，没有直接复制 PoseBridge YXZ 分量或对欧拉角逐项相减。

随后在同一 Renderer 进程的 **Person** 视图中执行实际 UDP 接收验证：

- `/ypr` 单轴与复合测试输入能改变人物姿态，归零测试输入能恢复正立。
- macOS 0.7 客户端连接真实 WT901BLE68，安装映射为右 −Y、前 +X、上 +Z，界面观察约 20 Hz。
  两路同时启用并持续增长，观察点的两路发送错误均为 0。
- 实际客户端最小化约 37 秒后，两路发送与 PoseBridge 心跳仍增长，发送错误保持 0；恢复窗口后保持同一连接。
- 在真实采集中点击 **Set Dolby forward**，Dolby 的 Last sent 归零，Renderer 人物由倾斜恢复正立。
  Tracking 原始角度仍约为 yaw 9°／pitch −63°／roll −31°，没有随 Dolby 回正归零；两路继续发送。

上述网络接收和独立回正已有 Renderer 画面验证，不仅依据 UDP 发送成功计数。
佩戴测试最初反馈左右反向；说明客户端回正按钮位置并在佩戴状态重新回正后，用户反馈“正常了”。
此时运行的仍是原坐标转换，因而保留与该实测版本一致的矩阵约定，没有额外翻转输出轴。
界面按钮补充 Recenter 字样和“佩戴、面向正前方、保持正立”的提示，防止把桌面姿态当成佩戴参考。
逐项记录左转／抬头／右倾及实时耳机监听声向的结果仍待补充，尚不宣称完整听音验收通过。
Renderer 当时已启用 Binaural 和 OSC head tracker，播放处于暂停；离线 BIN re-render 不作为头追听音验收。
本轮未重新执行 Windows／USB 实机测试；先前通信覆盖见 [客户端记录](2026-10-23-client.md)。

## 构建与交付

两台机器使用 Rust 1.98.0，复用既有 registry 和 target。macOS 在已有外置缓存盘上构建；Windows 保留原检出及未提交修改，
逐项核对同步基线和剩余空间后应用增量，不创建独立缓存。应用运行不依赖外盘。

应用包为提交前工作区产物，manifest 标记 `source_dirty=true`，记录可执行文件 SHA-256、架构和原生窗口 smoke 结果。
两平台 ZIP 均通过完整性与可执行文件哈希核对，均包含 Dolby 中文使用说明、字体及许可资源。
macOS 为本地 ad-hoc 签名包，Windows 未做发布者签名；本轮没有公证或发布到在线发行渠道。
