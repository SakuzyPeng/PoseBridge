# 电压与估算电量接入验证

日期：2026-09-21。沿用 C ABI 400、OSC 3、本地快照 schema 4；新增 `status.battery` JSON 字段。
复用两台机器的现有 checkout、target 和依赖缓存。

## 行为与依据

- `inspect` 查询一次电压；硬件采集连接后约 1 秒首读，随后每 30 秒读取 `0x64`，3 秒未响应记电量错误。
- 写请求与持续接收并行；只发 `FF AA 27 64 00`，不解锁、修改输出或保存配置。
- 使用官方 BLE 5.0 SDK 的电压分档表。百分比为估算值；有效模块电压范围 2.00–5.50 V，超过 4.30 V 时百分比为 null。
- 电量有独立年龄；错误／停止／断线使 fresh=false，90 秒过期，新连接清空旧值。

来源：[新版协议](https://wit-motion.yuque.com/wumwnr/docs/qnpb2lo3f0orduqe)、
[官方 SDK 固定版本](https://github.com/WITMOTION/WitBluetooth_BWT901BLE5_0/blob/9efaab0fdd6a06dc807bf80402e58aa91b431c6f/Windows_C%23/Wit.Example_BWT901BLE/ble5/Components/Bwt901bleProcessor.cs)。

## macOS 实机

WT901BLE68，版本 13115，原配置为 50 Hz、`0x61` 输出、九轴。设备在本轮始终接 USB 供电；未改设备设置。

| 路径 | 结果 |
|---|---|
| USB inspect | 电压 4.91 V，fresh=true，百分比 null |
| USB C ABI + OSC，33.5 秒 | 在约 1.027／31.041 秒取得两次读数，4.96／4.84 V，间隔约 30.014 秒；32 份含有效电压的状态心跳 |
| USB 姿态采集 | 1663 份姿态，约 49.65 Hz；无无效帧、丢弃字节、无效姿态或重连；停止后电量 fresh=false |
| USB 前后配置回读 | 配置与版本字段一致（排除观察时间） |
| BLE inspect + 8 秒 diagnose | 4.86 V，百分比 null；288 份姿态，约 49.84 个样本/秒；无无效帧、丢弃字节或重连 |

BLE 的样本数包含每通知批量交付，不等于通知频率。USB 接收端在停止前收到了 1662 个 OSC 姿态包，
源端发送计数为 1663；两者读取结束时刻不同，没有据此判定丢包。

第一次 USB 连续检查观察到 5 个丢弃字节，未通过当时的零丢弃断言；随后复查增加首个电量请求前的计数基线，
本表这一轮的启动与终态均为 0。初次 5 字节的出现时间未记录，不能据此归因于电量请求或断言为稳定性问题已解决。

实机读数高于单节锂电池范围，只确认了电压读取和传输链路。**没有验证拔掉 USB 后的电池百分比准确度、放电曲线、续航或充电状态，
也没有在 Windows 上重复本轮电量硬件测试。** 百分比换算由软件边界测试覆盖。

本机紧凑报告保存在 `target/benchmarks/battery-20260921/usb.json` 与 `ble.json`；不提交原始采样缓存。
